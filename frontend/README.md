# Qeedha Accounting - Frontend (Phase 2)

واجهة React + Vite + TypeScript + Tailwind (RTL) متصلة فعليًا بواجهات المرحلة
الثانية الخلفية (Products, Catalog, Inventory, Customers, Suppliers). لا
بيانات وهمية - كل شاشة تستدعي الـ API الحقيقي.

## التشغيل محليًا

```bash
npm install
cp .env.example .env.local   # عدّل VITE_API_BASE_URL إذا لزم
npm run dev
```

يفترض تشغيل الـ backend على `http://localhost:3000` (راجع `../backend/README.md`).

## الاختبارات

```bash
npm run test        # Vitest (وحدة/مكوّن) — 7/7 تنجح حاليًا
npm run test:watch  # نفسه، وضع مراقبة
npm run test:e2e    # Playwright — يتطلب backend يعمل ومهاجَر ومزروع مسبقًا
```

Vitest (`vite.config.ts` قسم `test`، `@testing-library/react` +
`@testing-library/user-event`): 3 ملفات تحت `src/pages/__tests__/`
(`LoginPage`, `RegisterPage`, `DashboardPage`).

Playwright (`playwright.config.ts`, `e2e/`): مجموعة **مُلتزَمة في
المستودع** (لم تعد سكربتات مؤقتة يدوية كما في مراحل سابقة) —
`golden-path.spec.ts` (الرحلة الكاملة تسجيل→...→تقارير→خروج/دخول) و
`tenant-isolation.spec.ts` (عزل منشأتين). يبدأ خادم Vite بنفسه فقط —
الـbackend يجب أن يكون يعمل مسبقًا. راجع `docs/TESTING.md` للتفصيل
الكامل.

## النطاق الحالي (Phase 2)

- تسجيل الدخول (بما فيه اختيار المنشأة لمن لديه أكثر من عضوية) + تسجيل منشأة جديدة.
- المنتجات: بحث، صفحات، إضافة (مع تصنيف/علامة/وحدة/باركود).
- التصنيفات/العلامات/الوحدات: عرض وإضافة.
- المخزون: عرض الأرصدة حسب المستودع، رصيد افتتاحي، تسوية مخزون.
- العملاء والموردون: بحث، صفحات، إضافة.
- لوحة تحكم بمؤشرات من بيانات حقيقية فقط (بدون أرقام وهمية).

## تصليب/جاهزية (Milestone 2)

- **RBAC**: كل صفحة الآن مُقيَّدة بصلاحيتها المطلوبة فعليًا (لوحة التحكم
  والفواتير كانتا الثغرتين المكتشفتين والمُصلَحتين).
  - `Promise.allSettled` بدل `Promise.all` في لوحة التحكم — فشل جزئي
    يعرض ما نجح فقط، لا شاشة فارغة.
- **حالات تحميل/خطأ**: كل صفحة تعرض "...جارٍ التحميل" أثناء جلب البدء
  و`ErrorBanner` عند الفشل.
- **انتهاء الجلسة (401)**: تجديد توكن فاشل يُسجِّل خروج المستخدم تلقائيًا
  ويعيد التوجيه لتسجيل الدخول، بدل شاشة باليات بطلبات فاشلة صامتة.
  (403 لا يزال بلا واجهة مخصصة — حد معروف، راجع `docs/TESTING.md`.)
- **استجابة (Responsive)**: شريط جانبي off-canvas تحت شاشات ضيقة (`md`)،
  وجداول البيانات (~20 جدولًا) تُمرَّر أفقيًا بدل كسر التخطيط.
- **Onboarding**: قائمة قصيرة من 8 خطوات على لوحة التحكم لتوجيه تاجر
  جديد لأول عملية بيع، قابلة للإخفاء، ليست معالجًا متعدد الشاشات.

  والإضافة لكل وحدة جديدة).
- معالج استيراد Excel.
