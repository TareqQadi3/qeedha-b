# استيراد Excel (Import Wizard) — تصميم (يُبنى في المرحلة 5)

## جاهزية المخطط (Schema Readiness) — بعد المرحلة 2

الكيانات المستهدَفة الأولى للاستيراد (منتجات، عملاء، موردون، أرصدة افتتاحية)
منفَّذة فعليًا بمعرّفات تفرّد على مستوى المنشأة تلائم الاستيراد الجماعي دون
تعارض بين تجّار مختلفين: `products.sku`، `product_barcodes.barcode`،
`customers.reference`، `suppliers.reference` — كلها `@@unique([companyId,
field])`. رصيد افتتاحي للمخزون له مسار مخصص بالفعل
(`InventoryService.setOpeningBalance`, يرفض إعادة التعيين فوق رصيد غير صفري
قائم) يمكن لـImport Wizard استدعاءه مباشرة لكل صف. **لا Wizard فعلي ولا
`import_jobs`/`import_job_rows` بعد** — هذا القسم توثيق جاهزية فقط.

## المبدأ
لا نفترض أسماء أعمدة ثابتة. كل تاجر لديه ملف Excel بتنسيق مختلف — الـWizard
يكتشف ويقترح، والمستخدم يؤكد، ولا شيء يُحذف أو يُعدَّل بصمت.

## الكيانات (مرجع — `DATABASE.md` §8)
`import_jobs` (نوع البيانات: منتجات/عملاء/موردون/مخزون/أرصدة افتتاحية، حالة،
Mapping كـ JSONB)، `import_job_rows` (نتيجة كل صف).

## خطوات الـWizard (كما في المواصفات)
1. رفع الملف وقراءته (xlsx/csv).
2. اكتشاف الأعمدة تلقائيًا (أسماء الرؤوس + عيّنة من البيانات).
3. اقتراح Mapping لأعمدة النظام المستهدفة (مثلًا "الاسم" → `products.name`).
4. كشف التكرار (بمقارنة SKU/الباركود/رقم الجوال حسب نوع البيانات).
5. كشف الحقول الناقصة الإلزامية.
6. كشف الأخطاء (نوع بيانات غير صحيح، قيمة سالبة لسعر... إلخ).
7. عرض Preview كامل قبل التنفيذ.
8. طلب تأكيد صريح من المستخدم.
9. تنفيذ الاستيراد ضمن معاملة قابلة للتراجع عند الفشل الجزئي.
10. تقرير نهائي: عدد الناجح، عدد الفاشل مع السبب، عدد المتجاوَز (تكرار).

## قاعدة صارمة
لا يُسمح بحذف أو Overwrite صامت لبيانات موجودة. أي تحديث لسجل موجود (بمطابقة
SKU مثلًا) يُعرض كـ "تحديث" صريح في الـPreview قبل التنفيذ، ويُسجَّل في
`audit_logs`.
