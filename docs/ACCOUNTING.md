# المحاسبة (Accounting) — تصميم (يُبنى في المرحلة 4)

## المبدأ
Double-Entry Accounting حقيقي — كل قيد يجب أن يتوازن (مجموع مدين = مجموع
دائن)، ويُنشأ تلقائيًا من العمليات التشغيلية، وليس إدخالًا يدويًا مزدوجًا.

## الكيانات (مرجع — انظر `DATABASE.md` §7 للتفاصيل الكاملة)
`chart_of_accounts`, `journal_entries`, `journal_lines`, `fiscal_periods`,
`opening_balances`.

## القيود التلقائية المتوقعة لكل حدث تشغيلي
| الحدث | القيد المبدئي |
|---|---|
| بيع (نقدي/بطاقة) | مدين: نقدية/بنك — دائن: إيرادات، دائن: ضريبة القيمة المضافة مستحقة |
| بيع (آجل/عميل) | مدين: ذمم مدينة — دائن: إيرادات، ضريبة |
| تكلفة البضاعة المباعة | مدين: تكلفة البضاعة المباعة — دائن: المخزون |
| شراء بضاعة | مدين: المخزون، ضريبة مدخلات — دائن: ذمم دائنة/نقدية |
| مصروف | مدين: حساب المصروف — دائن: نقدية/بنك |
| تسوية مخزون (نقص) | مدين: مصروف تالف/فاقد — دائن: المخزون |

هذا جدول توضيحي أولي؛ الترميز الدقيق لدليل الحسابات الافتراضي يُحدَّد عند بدء
المرحلة 4 (قد يحتاج نقاشًا معك حول دليل حسابات افتراضي مناسب للسوق السعودي).

## قواعد حرجة
- **لا تعديل على قيد مُرحَّل** — فقط قيود عكسية (reversing entries).
- **إغلاق الفترات المالية**: لا قيود بأثر رجعي على فترة مغلقة إلا بإعادة فتح
  صريحة + Audit trail.
- القيود اليدوية تمر بنفس مسار Audit Log مثل التلقائية.
- تقييم المخزون: FIFO أم Weighted Average — **قرار مفتوح يحتاج نقاشك** قبل
  التنفيذ (انظر `ARCHITECTURE.md` §9).
