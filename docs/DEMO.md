# بيانات تجريبية (Demo Seed)

`backend/scripts/demo-seed.ts` (Milestone 2) — سكربت واحد يُنشئ منشأة
تاجر تجريبية كاملة عبر Endpoints الحقيقية للـAPI (لا إدخال DB مباشر
إطلاقًا)، بحيث يمر بكل قيد فعلي في النظام (بذر دليل الحسابات، الأدوار
الافتراضية، إلخ) تمامًا كأي منشأة حقيقية.

## كيفية إنشاء منشأة تجريبية

يتطلب backend يعمل ومُهاجَر ومزروع بالفعل (`prisma migrate deploy` +
دور `qeedha_auth_lookup` + `npm run prisma:seed` — راجع
`backend/README.md`):

```bash
cd backend
BASE_URL=http://localhost:3000/api/v1 npm run demo:seed
```

`BASE_URL` اختياري — الافتراضي هو نفسه (`http://localhost:3000/api/v1`).

## ماذا يُنشئ

كل تشغيل (`main()` في `scripts/demo-seed.ts`) يُنشئ، بالترتيب:

1. **منشأة تجريبية واحدة** عبر `POST /auth/register-company` (مالك أول +
   فرع/مستودع رئيسيان يُنشآن ذرّيًا مع التسجيل، تمامًا كأي تسجيل حقيقي).
2. **4 منتجات** برصيد افتتاحي 200 وحدة لكل منتج (أرز، زيت زيتون، سكر،
   شاي).
3. **عميلان** («بقالة الأمل»، «سوبرماركت النور»).
4. **موردان** («شركة التوريد الغذائي»، «مؤسسة المواد الأساسية»).
5. **شراء واحد مُستلَم** (أول موردَين، أول منتجَين) — بحيث شاشات AP/
   التقارير ليست فارغة.
6. **بيع POS واحد مكتمل** (أول عميل، أول منتجَين، دفعة نقدية كاملة) —
   بحيث شاشات المبيعات/الفواتير/المحاسبة/التقارير ليست فارغة.
7. طباعة بيانات دخول المالك التجريبي (بريد + كلمة مرور) على `stdout` في
   نهاية التشغيل — **لا تُخزَّن في أي مكان آخر** بواسطة هذا السكربت.

## لا بيانات شخصية حقيقية

كل اسم في السكربت مُعلَّم صراحة `(Demo)`/`(Demo Owner)`/`(Demo Customer)`/
`(Demo Supplier)`، وكل بريد إلكتروني بنطاق `@qeedha-demo.local` (ليس
صندوق بريد فعلي قابل للتسليم) — لا بيانات شخصية حقيقية في أي مكان.

## ماذا يمكن أن تُظهر منشأة تجريبية

بعد التشغيل، يمكنك تسجيل الدخول ببيانات الاعتماد المطبوعة ورؤية كل
شاشة بالتطبيق تحتوي بيانات حقيقية غير فارغة فورًا: المنتجات، المخزون،
العملاء/الموردون، المشتريات، المبيعات/الفواتير، الحسابات/القيود،
التقارير المالية، والذمم.

**المرجع الكامل لما يعمل فعليًا من أول تسجيل حتى تقرير متوازن** هو
مجموعة Playwright المُلتزَمة (`frontend/e2e/golden-path.spec.ts`) —
راجع `docs/TESTING.md` "Playwright" بدل إعادة وصف المسار هنا؛ ذلك
السكربت هو المصدر الوحيد للحقيقة حول أي رحلة مستخدم كاملة تعمل فعليًا
عبر الواجهة الحقيقية، وقد نُفِّذ وتحقَّق منه فعليًا.

## Milestone 7 (Merchant Operations)

`demo-seed.ts` نفسه **لم يتغيّر** في Milestone 7 — البيع/الشراء
المُبذوران لا يزالان مدفوعَين بالكامل نقدًا، بلا مرتجعات أو تسويات بنكية
تلقائية. كل ميزات Milestone 7 (بيع آجل + تسديده، دفعة لمورد، مرتجع
مبيعات/مشتريات، تسوية بنكية) قابلة للتجربة يدويًا فورًا عبر الواجهة
الحقيقية على نفس المنشأة التجريبية بمجرد تسجيل الدخول — راجع
`docs/ACCOUNTING.md` "Milestone 7" لتفاصيل كل تدفق، و
`frontend/e2e/golden-path.spec.ts` (مُمتَد في Milestone 7) للمرجع الكامل
المُتحقَّق فعليًا عبر متصفح حقيقي.

## آمن لإعادة التشغيل

كل تشغيل يُولّد لاحقة عشوائية جديدة (`Math.random().toString(36)`)
ويُنشئ منشأة/بريد/SKU جديدة تمامًا في كل مرة — **لا يمس أو يعتمد على أي
تشغيل سابق**. يمكن تشغيله عدة مرات على نفس قاعدة البيانات بأمان لإنشاء
عدة منشآت تجريبية منفصلة.
