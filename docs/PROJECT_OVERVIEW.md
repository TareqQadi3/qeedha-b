# نظرة عامة على المشروع (Project Overview)

## ما هو هذا المشروع؟

برنامج محاسبي ونقاط بيع (POS) متكامل، مخصص للبقالات والسوبرماركت في السعودية.
المنتج **مستقل بالكامل** عن أي منتج آخر — بما في ذلك "قيّدها". يعمل بكامل وظائفه
بدون أي تكامل خارجي، ويمكن لاحقًا ربطه اختياريًا بخدمات خارجية (قيّدها هي أول
تكامل مخطط له، لكنها ليست الوحيدة).

## القاعدة المعمارية الحاكمة

> **البرنامج المحاسبي منتج مستقل. أي تكامل خارجي هو إضافة اختيارية فوق نظام
> يعمل بالكامل بدونه.**

هذه القاعدة تحكم كل قرار تصميمي في هذا المشروع:

- لا يعتمد Core Business Logic (POS، المبيعات، المخزون، المحاسبة) على أي
  Integration معيّن.
- طرق الدفع الأساسية (نقدي، بطاقة، تحويل) تعمل دائمًا بدون أي إعداد إضافي.
- أي طريقة دفع تأتي من تكامل خارجي (قيّدها أو غيرها) هي **إضافة** تُفعَّل من
  الإعدادات، ولا تُغيّر سلوك النظام الأساسي إن لم تُفعَّل أو انقطعت.
- لا نبني منطق قيّدها (رصيد، تمويل، خصم، تسوية) داخل هذا النظام — هذا مسؤولية
  قيّدها نفسها عبر API عندما يتوفر العقد الرسمي لها.
- لا نخترع تفاصيل API لأي نظام خارجي؛ التصميم يُجهَّز فقط لاستقبال عقد لاحق.

## من يستخدم النظام؟

- **صاحب المتجر (Owner)**: يدير المنشأة، الفروع، الإعدادات، التقارير المالية.
- **المدير (Manager)**: يدير فرعًا، الموظفين، المخزون، الأسعار ضمن صلاحياته.
- **الكاشير (Cashier)**: يبيع من نقطة البيع، يستقبل مدفوعات، مرتجعات محدودة.
- **المحاسب (Accountant)**: القيود، دليل الحسابات، التقارير المالية.
- **مسؤول المخزون (Inventory Manager)**: المخزون، الجرد، التحويلات، الاستلام.

## نطاق المرحلة الأولى (هذا التسليم)

Architecture + Domain Model + Database + Authentication + أساس النظام
(multi-tenancy, RBAC, audit log, integration layer skeleton). لا POS ولا
منتجات ولا محاسبة فعلية بعد — هذه تأتي بالمراحل التالية حسب `ROADMAP.md`.
